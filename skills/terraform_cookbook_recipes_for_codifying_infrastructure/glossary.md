# Glossary — Terraform Cookbook: Recipes for Codifying Infrastructure

Alphabetical. `(Ch N)` = chapter in the book.

- **Blast radius** — The potential scope of damage from a bad change; minimized through modularization, workspace isolation, least-privilege IAM, and small frequent applies (Ch 2.11)
- **can()** — Built-in function that returns `true`/`false` for whether an expression succeeds without raising an error; pairs with `try` for optimistic data access (Ch 3.11)
- **chomp** — Function that removes trailing newline characters from a string, useful after file reads (Ch 3.1)
- **cidrsubnet** — Function for carving subnets out of a parent CIDR block programmatically (Ch 3.7)
- **Consul KV** — HashiCorp Consul's key-value store, usable as a dynamic configuration surface for Terraform (Ch 4.8, 8.3)
- **Dependabot** — GitHub automation for keeping Terraform provider versions updated (Ch 2.9)
- **DevContainer / GitHub Codespaces** — Reproducible cloud dev environments that give every contributor identical Terraform tooling (Ch 2.10)
- **Drift** — Divergence between the Terraform state and the real infrastructure; detected via state inspection, addressed through import or re-apply (Ch 6.10, 9.10)
- **Dynamic secrets** — Secrets generated on demand with short TTLs (e.g. Vault dynamic credentials) rather than long-lived shared values (Ch 7.9)
- **for_each** — Meta-argument for creating one resource instance per map/set element, with stable addressing (Ch 3.12)
- **HCL (HashiCorp Configuration Language)** — Terraform's declarative language for describing desired infrastructure state (Ch 1)
- **HCP Terraform (formerly Terraform Cloud)** — HashiCorp's managed platform for remote state, collaboration, policy as code, cost management, and remote operations (Ch 6)
- **Helm** — Kubernetes package manager; Terraform drives Helm deployments via the Helm provider (Ch 5.10–5.11)
- **k2tf** — Utility that converts Kubernetes YAML manifests into Terraform HCL (Ch 5.6)
- **kubernetes_manifest** — Terraform resource type for scheduling containers on Kubernetes with HCL rather than YAML (Ch 5.5)
- **local-exec provisioner** — Runs a shell command on the machine running Terraform; demonstrative only, unsuitable for most production work (Ch 2.5)
- **Module** — A reusable, composable Terraform building block wrapping resources behind inputs/outputs (Ch 1.5, 4.5)
- **Nomad** — HashiCorp orchestrator that Terraform can schedule containers onto (Ch 5.12)
- **OpenTofu** — The open-source fork of Terraform; this book's examples and practices are written to work with both (Ch 1)
- **OPA (Open Policy Agent)** — Policy-as-code engine for validating Terraform plans against organizational rules (Ch 2.6)
- **Postcondition** — `lifecycle` check run after a resource is created/updated to verify the resulting state (Ch 2.5)
- **Precondition / variable validation** — `validation` block on a variable, checked before Terraform touches any resources (Ch 2.5)
- **Provider** — Plugin that lets Terraform manage an API's resources; version-constrained and, where needed, instantiated multiple times via aliases (Ch 1.4, 1.9, 4.11)
- **Remote operations** — Running plan/apply on HCP Terraform's infrastructure instead of a local/laptop run; suited to large-scale deployments (Ch 6.9)
- **Sentinel** — HCP Terraform's policy-as-code framework for embedding governance into runs (Ch 6.7)
- **State** — Terraform's record of managed infrastructure and mappings between config and real resources (Ch 1.6, 6.10, 9.4)
- **State locking** — Prevention of concurrent state modifications that could corrupt state (Ch 6.10)
- **templatefile()** — Function that renders a template file with variables, used to generate configs (Ch 3.9, 8.8)
- **TFSec** — Static security scanner for Terraform configuration (Ch 2.4)
- **TFLint** — Pluggable linter that catches provider-specific errors before plan/apply (Ch 2.3)
- **terraform-docs** — Tool that auto-generates documentation for modules (Ch 2.7)
- **terraform console** — Interactive REPL for evaluating expressions against state — the "playground" for functions (Ch 1.6, 2.2)
- **trimspace** — Function that strips leading and trailing whitespace from user input (Ch 3.1)
- **try()** — Function that attempts expressions in order and returns the first that succeeds; falls back gracefully (Ch 3.11)
- **Vault** — HashiCorp's secrets manager; Terraform consumes static and dynamic secrets from it (Ch 7.2, 7.4, 7.9)
- **Workspaces** — Isolated state instances of a configuration, used for environment separation (Ch 8.7, 10.1)
