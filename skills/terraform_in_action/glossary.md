# Glossary — Terraform in Action

**Acceptance tests** — Go tests (provider schema + resource) gating `TF_ACC=1`; required before calling a provider production-ready (Ch 11)
**Arguments / Attributes / Computed attributes** — resource inputs; outputs readable from state; values only known after apply (e.g. `id`, `arn`) (Ch 1)
**Autoscaling group (ASG)** — collection of EC2 instances treated as one scaling unit behind a launch template; one LB target (Ch 4)
**Backend** — determines where state is stored/loaded; standard backends (S3 etc.) vs enhanced (Terraform Cloud/Enterprise remote operations) (Ch 6)
**Blue/Green deployment** — two environments, one live; deploy to idle, cut over via router (LB or DNS); enabling fast rollback (Ch 9)
**Buildspec** — AWS CodeBuild YAML spec of build commands; one per pipeline stage (Ch 12)
**Bubble-up / Trickle-down** — child module outputs rise to root, then pass down as sibling module inputs (Ch 4)
**Canary deployment** — ramp a % of traffic to the new version with fast rollback and feature toggles (Ch 9)
**Cloud-agnostic** — one toolchain deploys to any cloud via providers (Ch 1)
**CodeStar connection** — Terraform-managed GitHub auth; created as PENDING, must be authenticated manually in the console (Ch 12)
**Configuration drift** — out-of-band change to deployed infra; detected by plan (state vs desired), corrected on apply (Ch 2)
**Configuration management (CM)** — tools (Ansible, Chef, Puppet) deploying software onto existing servers; mutable infrastructure (Ch 1, 9)
**create_before_destroy** — lifecycle flag making a force-new update build the replacement before destroying the old (Ch 9)
**Data source** — read-only resource implementing only Read(); `data "<type>" "<name>" { query constraints }` (Ch 1)
**Declarative programming** — describe what, not how; "destination, not the journey" (Ch 1)
**Dynamic block** — generates repeating nested config blocks from complex types; rarest Terraform expression (Ch 7)
**Dynamic secrets** — just-in-time short-lived credentials created on demand and revoked after use (Vault, ASM) (Ch 13)
**Execution plan** — CLI output of intended actions (+ create, ~ update, - destroy, -/+ replace); generated identically by plan and apply (Ch 1–2)
**External data source** — executes arbitrary code and returns JSON to Terraform, running even during plan; most dangerous resource type (Ch 13)
**Flat module** — many small .tf files in one module, one file per component; less boilerplate, higher coupling (Ch 6)
**Federation** — joining clusters across datacenters/clouds (Consul↔Consul, Nomad↔Nomad WAN) into one control plane (Ch 8)
**for_each** — meta argument creating one instance per map key/set entry; keyed addressing `[<type>.<name>["<key>"]]` (Ch 7)
**Force-new attribute** — changing it taints/replaces the whole resource (destroy + recreate) (Ch 2)
**HCL** — HashiCorp Configuration Language; human-readable, JSON-compatible 1:1 (Ch 1)
**Heredoc** — `<<-EOT ... EOT` multiline string syntax; leading whitespace ignored (Ch 2)
**Hybrid cloud** — at least one private + one public cloud, vs multi-cloud (multiple public clouds) (Ch 8)
**Implicit vs explicit dependency** — created by attribute interpolation (preferred) vs declared with `depends_on` (last resort, document why) (Ch 3)
**Implicit vs explicit provider** — default provider config vs per-resource `provider =` override for multi-region or (google-beta) beta APIs (Ch 7)
**Lifecycle block** — `create_before_destroy`, `prevent_destroy`, `ignore_changes` flags (Ch 9)
**Local value** — named expression result, like a function's local temporary symbols (Ch 3)
**count** — meta argument creating N indexed instances `[N]` accessed with `count.index`; prefer for_each unless position matters (Ch 3, 7)
**Managed vs unmanaged resource** — full CRUD vs read-only (data source); only managed ones persist state (Ch 2, 11, 13)
**Module** — self-contained code package; a function with side effects (the resources it provisions) (Ch 4)
**Module expansion** — `for_each`/`count` on a module block (0.13+); declare once, expand per key (Ch 10)
**Namespace** — project identifier used for unique naming; right-pad with `random_string` for global uniqueness (Ch 4–5, 12)
**Provisioner** — script hook on create/destroy (file, local-exec, remote-exec); declared anti-pattern, last resort (Ch 7, 9, 13)
**Provider** — Go plugin interfacing an external API over RPC; exposes resources/data sources; Registry-distributed (Ch 1, 11)
**SAS token** — Azure presigned access URL granting scoped, time-boxed blob read (Ch 5)
**Raft consensus** — cluster server protocol; servers must be an odd count for quorum, one elected leader (Ch 8)
**Race condition** — two entities acting on one state file → corrupted state; prevented by backend locking (Ch 6)
**Raft / quorum — see Federation**
**Registry (Terraform Registry)** — public source of provider binaries and modules; modules need repo `terraform-<PROVIDER>-<NAME>`, README, standard structure, semver (Ch 4, 6)
**Resource** — the core element; `resource "<type>" "<name>" { ... }` implementing the CRUD schema interface (Ch 1)
**Root module** — directory where apply runs; wires child modules and exposes outputs (Ch 4)
**Sentinel** — HashiCorp policy-as-code DSL (sandbox, rule-based) checked between plan and apply; Enterprise-only (Ch 13)
**Serverless** — pay-as-you-go + minimal ops overhead; between PaaS and SaaS (Ch 5)
**Shim module** — a module carrying a build artifact so `terraform init` downloads it; supply-chain caution (Ch 5)
**Splat expression** — `list[*].attr` sugar for a for expression; lists only (Ch 10)
**State (terraform.tfstate)** — plaintext JSON record of managed resources; only resources, data sources, and outputs store state (Ch 2, 13)
**Static secrets** — long-lived credentials (passwords, tokens); pass as env vars, else git-ignored secrets.tfvars (Ch 13)
**Strangler façade** — incrementally replace a wrapped legacy stack (ARM/CloudFormation) with native Terraform (Ch 5)
**Template file** — `${...}` interpolation over passed vars only, e.g. `templatefile(path, vars)`; scope limited to arguments (Ch 3)
**Two-stage deployment** — Terraform for static infra; CI/CD (or Ansible/Nomad) for dynamic app deployment (Ch 7–9)
**taint / untaint** — mark one resource for destroy+recreate on next apply (rotate keys), or undo it (Ch 10)
**Terraform Cloud / Enterprise** — HashiCorp's SaaS/on-prem automation layer; TeC = TFE minus private datacenter (Ch 6, 12)
**terraform-exec** — HashiCorp Go library for programmatic Terraform CLI calls; integration testing (Ch 10)
**tfvars** — variable value files (terraform.tfvars auto-loaded; others via -var-file) (Ch 3, 10, 13)
**Trace logging (TF_LOG=trace)** — dumps signed credentials and full API traffic into logs; debugging only (Ch 13)
**Validation block** — per-variable `condition`/`error_message` rules, unlimited count (Ch 3)
**Workspace** — named state slot for one configuration; parameterize environments with per-workspace var-files (Ch 6)
