# Glossary

**Ad Hoc Scripting** — first-level IaC: shell/PowerShell/Python scripts automating repetitive tasks; non-idempotent, no platform independence (Ch 1)
**AKS (Azure Kubernetes Service)** — managed Kubernetes; provisioned via `azurerm_kubernetes_cluster` with node pools, network profile, RBAC (Ch 10)
**AuditEvent** — Key Vault log category capturing every secret read/update, shipped to Log Analytics via a Diagnostic Setting (Ch 7)
**Backend** — configuration block declaring where state is stored (`backend "azurerm"` etc.); `terraform init` migrates state to it (Ch 2, Ch 5)
**CIDR block** — IP range notation (e.g. `10.0.0.0/16`) defining VPC/VNet space; subnets must be disjoint within it (Ch 8)
**Compliance testing** — policy checks (OPA Rego, tfsec, checkov) evaluated against the JSON plan to block violations pre-apply (Ch 9)
**count** — meta-argument producing N identical copies of a resource, addressable via `count.index` (Ch 3)
**Data source** — `data` block fetching existing infrastructure/external values (vault secrets, AMIs, images, cluster configs) without creating resources (Ch 1, Ch 7, Ch 10)
**Drift** — divergence between real infrastructure and the state file, from external/manual changes or auto-scaling; detected by plan, reconciled by refresh→apply (Ch 5)
**Dynamic block** — generates repeated nested sub-blocks (e.g. ingress rules) inside one resource from a list object (Ch 3)
**Dynamic secrets** — Vault-issued short-lived credentials that auto-expire and are revoked at lease end (Ch 10)
**file provisioner** — copies local files/directories to a new remote resource over SSH/WinRM using a `connection` block (Ch 6)
**for_each** — meta-argument creating keyed resources from a map/set; stable addresses `type.name["key"]` (Ch 3)
**HCL** — HashiCorp Configuration Language; declarative, block-structured, JSON-compatible configuration language (Ch 1, Ch 2)
**Immutable infrastructure** — never modify deployed resources; replace instead — eliminates drift (Ch 1)
**Import** — `terraform import <addr> <id>` brings existing resources under Terraform without recreation; verified by a "No changes" plan (Ch 9)
**Interpolation** — `${...}` embedding expressions/references in strings (Ch 3)
**KPIs (Terraform)** — execution speed, resource utilization, error rates, maintainability, deployment frequency/lead time (Ch 9)
**Kubernetes provider** — manages namespaces, deployments, services in HCL; wired with kube_config data from AKS/EKS clusters (Ch 10)
**Locals** — internal named computations inside modules, hidden from consumers (Ch 4)
**Module** — reusable package of resources defined by inputs (variables), internal locals, and outputs; sourced locally, from Git (with `?ref=` tags), or registries (Ch 4, Ch 10)
**Mutable infrastructure** — patching servers in place (Chef/Puppet era); produces configuration drift (Ch 1)
**null_resource** — dummy resource used to host provisioners driven by a `triggers` map, so they re-run when trigger values change (Ch 6)
**Plan file (`-out=`)** — saved plan applied verbatim so reviewed changes are exactly what deploys (Ch 2)
**Provisioner** — executes `file` / `local-exec` / `remote-exec` actions at creation/destruction; failure taints the resource (Ch 6)
**Provider** — plugin connecting Terraform core to a platform's APIs (azurerm, aws, kubernetes); pinned in `required_providers` (Ch 1, Ch 2)
**Registry** — public/private repository for discovering, versioning, and sharing modules and providers (Ch 4, Ch 10)
**Remote-exec provisioner** — SSHes into a newly created resource to run commands; keep small and idempotent (Ch 6)
**Resource graph** — directional dependency graph Terraform builds; orders creation, parallelizes independent work (Ch 1)
**sensitive = true** — variable/output flag suppressing value display in plan output (Ch 10)
**Service principal** — dedicated Azure identity (appId/client_id, password/client_secret, tenant) for non-interactive Terraform auth (Ch 2)
**State file (`terraform.tfstate`)** — authoritative record of managed resources and attributes; sensitive; the basis of plan/apply deltas (Ch 5)
**State locking** — serialization of concurrent Terraform runs against one backend; stale locks need `force-unlock` (Ch 5, Ch 9)
**Tainted resource** — resource whose provisioner failed; Terraform destroys and recreates it on the next run (Ch 6, Ch 9)
**State migration** — moving state between backends (init + confirm) or re-addressing resources (`state mv`) during refactors (Ch 5)
**Terratest** — Go library for Terraform tests: `InitAndApply`, output assertions, `defer terraform.Destroy` (Ch 9)
**tfvars** — variable-value files (and `TF_VAR_*` env vars) supplying inputs at runtime; sensitive ones stay out of version control (Ch 2, Ch 3)
**Validation (variable) block** — input constraints that fail fast at plan with readable errors (Ch 3)
**Validation testing** — testing deployed behavior (HTTP 200 via `HttpGetWithRetry`), not just code (Ch 9)
**Vault** — HashiCorp tool for dynamic secrets and ephemeral credentials; Azure engine issues role-scoped creds via `azure/creds/<role>` (Ch 10)
**Workspace** — separate state files for one configuration, isolating dev/test/prod runs (Ch 1, Ch 2)
