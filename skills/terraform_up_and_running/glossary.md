# Glossary — Terraform Up & Running, 3rd Ed.

**ALB (Application Load Balancer)** — L7 load balancer: listener + rules + target groups with health checks; use for HTTP/HTTPS web apps (ch02)
**Accidental vs essential complexity** — "No Silver Bullet" (Brooks): production infrastructure is mostly essential complexity; the checklist must be considered, not skipped (ch08)
**Alias** — an extra named provider configuration within one module; selected via `provider = aws.<alias>` (ch07)
**Approval workflow** — CI step where a reviewer sees code + plan before apply; every prod infra deploy should pass through one (ch10)
**Backend** — mechanism determining where state is loaded/stored; default is `local`, teams use remote (S3/GCS/Azure/TFC) (ch03)
**Backend key** — unique state path per module; never reuse a key across modules (silent state overwrite) (ch03)
**Bus factor** — number of people you can lose before you can no longer operate; IaC lowers it (ch01)
**Canary** — comparison of a new copy of infra/app against the old ("control") in production before switching (ch10)
**CAMS** — DevOps values: culture, automation, measurement, sharing (Brikman/Juvenal) (ch01)
**Configuration alias** — alias declared via `configuration_aliases` in `required_providers` so a reusable module declares need and the root module injects (ch07)
**Configuration drift / snowflake servers** — each server ends up subtly different when managed manually; IaC's explicit purpose (ch01)
**Data source** — read-only lookup that creates nothing (e.g. Default VPC, AMI IDs) (ch02, ch07)
**declarative vs procedural** — declarative config declares end state (Terraform); procedural encodes steps (many ad hoc tools) (ch01)
**Deployment** — Kubernetes declarative app manager nudging the cluster toward declared intent; k8s reconciliation loop (ch07)
**Dependency injection** — module deps modeled as optional inputs defaulting to null so mock/test values can replace data sources (ch09)
**Escape hatch** — provisioners, null_resource, external data source: last resorts for provider gaps (ch08)
**examples folder** — per-module manual + automated test harness and executable documentation; every module gets examples, every example gets tests (ch08, ch09)
**Feature toggle** — if-statement default-off switch separating deploy from release (ch10)
**Golden Rule of Terraform** — "The main branch of the live repository should be a 1:1 representation of what's actually deployed in production" (ch10)
**IAM role / instance profile** — no-permanent-credentials auth for machines; instance profile attaches role to EC2 (ch06)
**Idempotence** — running the tool repeatedly yields the correct same result regardless of starting state (ch01)
**Immutable infrastructure** — never modify deployed servers; build a new image, redeploy, kill the old (functional-programming-inspired) (ch01, ch02)
**Implicit dependency** — creation ordering inferred from references between resources; visible via `terraform graph` (ch02)
**Inline block** — sub-config nested in a resource (e.g. `ingress`); conflicts with separate resources — never mix both styles (ch04)
**Input variable** — parameterized value, the module's API; set via `-var`, `TF_VAR_<name>`, default, or prompt (ch02, ch04)
**Instance metadata endpoint** — `http://169.254.169.254`, where EC2 exposes temporary role credentials (ch06)
**IaC (Infrastructure as Code)** — define/deploy/update/destroy infrastructure as text files and a tool (ch01)
**KMS / CMK** — AWS managed AES encryption; customer managed key + alias (ch06)
**Launch configuration** — immutable per-instance template for an ASG; needs create_before_destroy when changed (ch02)
**Live repo vs modules repo** — live repo = what's deployed per env ("houses"); modules repo = reusable versioned modules ("blueprints") (ch10)
**LocalStack** — endpoint mocker for testing; judged impractical at scale (ch09)
**locals** — module-private, non-overridable computed values (`local.<NAME>`); DRY within one config (ch04)
**LockID** — exact DynamoDB hash-key name (type "S") required for S3-backend state locking (ch03)
**Meta-parameters** — `count`, `for_each`, `lifecycle`: control Terraform behavior, not resource config (ch05)
**min_elb_capacity** — how many servers must pass ALB health checks before the new ASG counts as deployed (ch05)
**moved block** — declarative, committable state migration (Terraform 1.1+); success = plan shows no changes (ch05)
**OIDC** — federated CI auth (e.g. GitHub Actions → AWS STS) avoiding stored credentials (ch06)
**Out-of-band change** — manual UI/API edit; visible as drift in random `terraform plan` runs (ch10)
**Partial backend configuration** — empty backend block + `terraform init -backend-config=backend.hcl`; enables env/test isolation (ch03, ch09)
**Policy as code** — compliance rules over plans/code in Rego (OPA), Sentinel, YAML, or Go (ch09)
**precondition / postcondition** — lifecycle checks before apply / after apply on resources and data sources (Terraform 1.2+) (ch08)
**prevent_destroy** — lifecycle guard that errors on destroy of critical resources (ch03)
**Promotion** — deploying the same immutable artifact (Git tag / image) dev → stage → prod (ch10)
**Provisioner** — escape hatch for post-deploy config; prefer User Data (ch08)
**Provider** — plugin (Go binary over RPC) per platform (aws_, azurerm_) claiming resource prefixes (ch01, ch07)
**Provider local name** — unique key for a provider in a module; keep the preferred name (ch07)
**Reconciliation loop** — Kubernetes continuously nudges cluster toward declared intent (ch07)
**Reusable module** — never applied directly, no provider blocks, exposes its contract through variables/outputs (ch04, ch07)
**Root module** — the unit you run `apply` on; owns provider blocks (ch04, ch07)
**sensitive = true** — hides a value from plan/apply logs, NOT from state files (ch06)
**Server template/image** — self-contained snapshot of OS + software (VM image, Docker container) (ch01)
**State file** — JSON mapping config resources to real-world IDs; private API, never hand-edit (ch03)
**Static analysis** — parse code without executing: `validate`, tfsec, tflint, Terrascan (ch09)
**sops** — transparent edit-and-encrypt tool for in-VCS secret files (ch06)
**Template file** — `templatefile(PATH, VARS)` renders externalized scripts, e.g. long user_data (ch03)
**Terratest** — Go library: InitAndApply → assert on outputs → defer Destroy (ch09)
**test pyramid** — many unit > fewer integration > few E2E; per-layer brittleness compounds (99.9%^N) (ch09)
**Terraform import** — bring out-of-band infra into state (address + provider-specific ID) (ch05)
**Terraform workspace** — named isolated state file for one config; for experiments, not environments (ch03)
**TF_VAR_<name>** — env-var convention for input variables, keeps secrets out of code (ch03, ch06)
**validation block** — per-variable checks (Terraform 0.13+); conditions can reference only their own variable (ch08)
**Version pinning** — pin all three dependency layers: Terraform core, providers (with lock file), modules (?ref= semver tags) (ch08)
**wait_for_capacity_timeout** — default 10 minutes before a failed deploy aborts and auto-rolls-back (ch05)
